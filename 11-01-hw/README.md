### Задание 1. СУБД

### Кейс
Крупная строительная компания, которая также занимается проектированием и девелопментом, решила создать
правильную архитектуру для работы с данными. Ниже представлены задачи, которые необходимо решить для
каждой предметной области.

Какие типы СУБД, на ваш взгляд, лучше всего подойдут для решения этих задач и почему?

1.1. Бюджетирование проектов с дальнейшим формированием финансовых аналитических отчётов и прогнозирования рисков.
СУБД должна гарантировать целостность и чёткую структуру данных.

Ответ: Для этой задачи лучше всего подойдут реляционные СУБД (SQL), например PostgreSQL или MySql. Они обеспечивают высокую целостность, надежность и структурированность данных, гарантируют выполнение транзакций.

1.1.* Хеширование стало занимать длительно время, какое API можно использовать для ускорения работы?

Ответ: Использовать библиотеки OpenSSL/Crypto++ которые обращаются к инструкциям процессора (при наличии) для вычисления хэша аппаратно

1.2. Под каждый девелоперский проект создаётся отдельный лендинг, и все данные по лидам стекаются в CRM к
маркетологам и менеджерам по продажам. Какой тип СУБД лучше использовать для лендингов и для CRM?
СУБД должны быть гибкими и быстрыми.

Ответ: Для лендингов лучше использовать документо-ориентированные NoSQL СУБД, например MongoDB. Структура данных в лендингах может стремительно меняться и тут пригодяится гибкость и высокая скорость таких СУБД. Для crm лучше использовать реляционную бд, например PostgreSQL, так как в в такой системе важны связи между клиентами, целостность данных, анализ и сложные выборки данных.

1.2.* Можно ли эту задачу закрыть одной СУБД? И если да, то какой именно СУБД и какой реализацией?

Ответ: Да, это возможно. Например в PostgreSQL можно работать с классическими таблицами и создавать специальные таблицы где будет поле с типом данных jsonb для хранения документов. 

1.3. Отдел контроля качества решил создать базу по корпоративным нормам и правилам, обучающему материалу
и так далее, сформированную согласно структуре компании. СУБД должна иметь простую и понятную структуру.

Ответ: Для этой задачи подойдут иерархическая или сетевая модель данных, либо просто реляционная БД с простой структурой.

1.3.* Можно ли под эту задачу использовать уже существующую СУБД из задач выше и если да, то как лучше это
реализовать?

Ответ: Да, можно использовать PostgreSQL. Например создать две таблицы - departments и documents. У documents поля: id (первичный ключ), parent_id (ссылка на id в этой же таблице для иерархии), title, content, department_id (связь один к одному с отделом-владельцем)

1.4. Департамент логистики нуждается в решении задач по быстрому формированию маршрутов доставки материалов
по объектам и распределению курьеров по маршрутам с доставкой документов. СУБД должна уметь быстро работать
со связями.

Ответ: Здесь лучше всего подойдут графовые СУБД (NoSQL) , например ArangoDB. множество связей (путей) между объектами и поиск кратчайшего пусти между ними решается с помощью графов.

1.4.* Можно ли к этой СУБД подключить отдел закупок или для них лучше сформировать свою СУБД в связке с СУБД
логистов?

Ответ: Лучше создаю свою реляционную СУБД в связке с субд из ответа выше.

1.5.* Можно ли все перечисленные выше задачи решить, используя одну СУБД? Если да, то какую именно?

Ответ: Да, технически можно использовать одну реляционную PostgreSQL потому что она позволяет хранить документы, древовыидные данные где есть родители и дети и графы тоже (но работа с графами на больших объемах данных будет гораздо медленнее)

### Задание 2. Транзакции

2.1. Пользователь пополняет баланс счёта телефона, распишите пошагово, какие действия должны произойти для того, чтобы
транзакция завершилась успешно. Ориентируйтесь на шесть действий.

Ответ:
 
1. Старт транзакции, баланс пользователя фиксируется для изменения
2. Создается запись-счет со всеми необходими сопуствиующими записями
3. Отправляется команда в платежную систему на прием (обработку платежа)
4. Обновляется статус записи-счета в зависимости от успешности/неуспешности/таймаута проведения платежа
5. Увеличивается баланс пользователя если операция прошла успешно
6. Коммит транзакции (сохраняем изменения)

2.1.* Какие действия должны произойти, если пополнение счёта телефона происходило бы через автоплатёж?

Ответ: Разница только в пункте 3, платежная система не ждет когда пользователь подтвердит списание, а пробует списать средства автоматически:

1. Старт транзакции, баланс пользователя фиксируется для изменения
2. Создается запись-счет со всеми необходими сопуствиующими записями
3. Отправляется команда в платежную систему на автоматическое списывание средств
4. Обновляется статус записи-счета в зависимости от успешности/неуспешности/таймаута проведения платежа
5. Увеличивается баланс пользователя если операция прошла успешно
6. Коммит транзакции (сохраняем изменения)

### Задание 3. SQL vs NoSQL

3.1. Напишите пять преимуществ SQL-систем по отношению к NoSQL.

Ответ: 

1. ACID-транзакции. Гарантия надежность и целостность данных.
2. Удобно читать, расширять и работать с отношениями между данными в таблицах (relations), потому реляционные бд так и называются
3. Мощный язык запросов (SQL), который позволяет делать сложные выборки с объединением данных из многих таблиц (JOIN), агрегацией и фильтрацией.
4. Нормализация. Позволяет избежать дублирования данных.
5. SQL является стандартизированным языком, он един для различных субд (PostgreSQL, MySQL, Microsoft SQL Server, Oracle). Разработчику не нужно изучать новый язык запросов.

3.1.* Какие, на ваш взгляд, преимущества у NewSQL систем перед SQL и NoSQL.

Ответ: 

1. NewSQL умеют распределять данные и нагрузку на тысячи узлов, сохраняя при этом ACID-транзакции и SQL-интерфейс (горизонтальная масштабируемость)
2. Высокая производительность при обработке транзакций (OLTP) в распределенных средах

### Задание 4. Кластеры

Необходимо производить большое количество вычислений при работе с огромным количеством данных, под эту задачу
выделено 1000 машин.

На основе какого критерия будете выбирать тип СУБД и какая модель *распределённых вычислений*
здесь справится лучше всего и почему?

Ответ: Главный критерий - это большое количество вычислений над большим кол-вом данными. Тут лучше всего подойдет тип MPP (Massively Parallel Processing) например ClickHouse. Такое решение подходит так как в MMP все данные равномерно распределены по узлам и сложные запрос к данным разбивается на множество мелких подзапросов, результаты которых в конце суммируются. Это дает большую производительность на больших объемах данных
